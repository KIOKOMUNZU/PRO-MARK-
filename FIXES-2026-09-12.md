# PRO-MARK 3.9.7 — Academic Year, Terms, Tabs & Teacher Mark Entry Fixes

## Reference workbook used
The workbook `KAUTI SCHOOL 2026 TERM 3 MARKS.xlsx` was used only as a reference for the **TEACHERS** and **MARK ENTRY** sheets. Teacher names, learner names, marks, passwords, classes and subjects from the workbook were **not hard-coded into the application**.

## Fixes
1. Fixed administrator navigation so `Mark Entry`, `User & Role Control`, and `Mark Entry Control` are treated as real portal modules and can be opened/hidden like the other tabs.
2. Rebuilt the teacher Mark Entry selector flow around the requested five steps:
   **Academic Year → Term → Assessment → Class → Subject**.
3. Teacher selectors are populated from the logged-in teacher's database assignments; teachers do not receive unrelated classes or subjects.
4. Terms are loaded dynamically from the selected academic year.
5. Existing academic years automatically receive missing Term 1, Term 2 and Term 3 rows when academic years/terms are loaded. This is idempotent and does not create duplicate terms.
6. Assessments displayed in Mark Entry are read from the database. The browser does not manufacture assessment records.
7. Existing mark auto-save/manual-save logic remains in place.
8. Fixed an extra PostgreSQL parameter in the class-subject lookup used by bulk assessment setup.
9. Updated the smoke check to validate the actual 3.9.7 Mark Entry and navigation controls.

## Validation
- All JavaScript files pass `node --check`.
- `npm run check` passes.

## Additional correction after direct workbook/code inspection
9. Wired the teacher Mark Entry controls so changing **Academic Year** reloads Terms and Assessments, changing **Term** reloads Assessments, changing **Assessment** reloads Classes, changing **Class** reloads Subjects, and changing **Subject** loads the correct teacher assignment and learner roster.
10. Removed navigation buttons for modules the signed-in role cannot access, so unauthorized modules are not presented as inactive/dead tabs.
11. Teacher-role users now open directly on **MARK ENTRY**; administrators still open on the administrator workspace.
12. The Kauti workbook's `TEACHERS` and `MARK ENTRY` sheets were inspected directly. The importer remains database-driven and does not hard-code the workbook's teachers, learners, classes, subjects or marks.
13. Imported standard assessments are created as OPEN so imported mark sheets remain usable for teacher mark entry; existing assessment status is not forcibly changed by the application.
